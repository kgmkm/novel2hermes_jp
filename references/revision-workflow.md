# 推敲ワークフロー

小説の推敲は、本文執筆前（プロット段階）と本文執筆後（校正段階）の2回行う。

---

## Phase A: プロット段階の推敲（本文執筆前）

本文を書く前に、プロット自体の整合性を検証する。

### A-1. タイムライン検証

各章の日付・時刻・季節を書き出し、矛盾がないか確認する。

```
序章: 大正12年 晩夏 1日目〜3日目
  1日目 夕方: 灯と九十九の出会い
  2日目: 狐火の渓谷
  2日目 夜: 両親死亡
  3日目 朝: 九十九が灯を里に返す
第1章: 昭和8年 初秋（10年後）
  ...
```

### A-2. キャラ知識状態チェック

各シーンの冒頭で、キャラクターがその時点で「何を知っていて、何を知らないか」を明記する。

```
Scene 2: 灯が九十九の社を再訪する
- 灯の知識: 九十九がこの山に棲むと知っている。両親が殺された真相は知らない。
- 九十九の知識: 灯が退魔師になったことは知らない。灯の顔を覚えていない。
```

これにより、キャラが知らないことを言わせてしまうミスを未然に防ぐ。

### A-3. 伏線整合性チェック

全章の伏線を一覧にし、張り→回収の対応が取れているか確認する。

```
伏線: 蛍の墓 → 張り:序章 / 回収:第3章
伏線: 「また、あえる？」 → 張り:序章 / 回収:第3章
```

---

## Phase B: 本文段階の推敲（本文執筆後）

### B-1. 対話チェーン検証

台詞を書いた後、以下の3点を確認する：

1. この台詞の論理的前提は何か？
2. その前提は物語中で確立されているか？
3. 話者はその前提を知りうる立場か？

例：
```
九十九「おまえは、あの女に、よく似ていた——」
灯「……私は、あなたの——代わりだったんですか」 ← 問題
```
「あなたの代わり」の指示対象が「500年前の女性」だが、灯はこの場で初めてその話を聞いた。論理的前提が未確立。

修正案：灯が直接受けるべき感情に変更する。
```
灯「……だから。私を——守ってくださったんですか」
```

### B-2. 指示語の射程チェック

対話中の指示語（これ/それ/あれ/その/あの/あなたの）を抽出し、指示対象を明示的に確認する。

| 指示語 | 出現箇所 | 指示対象 | 問題 |
|--------|----------|----------|------|
| あなたの | 第3章「あなたの代わり」 | 九十九 | → 九十九本人を指すが文脈上不適切 |

### B-3. 世界制約チェック

プロジェクトの世界観に存在しない語彙・概念を使っていないか、台詞と地の文を照合する。

**チェック方法：**
1. 世界観保存時に「この世界に存在しないもの」リストを作成する（planning-workflow 1-2 参照）
2. 本文完成后、全台詞を一行ずつスキャンし、リストと照合する
3. 現代語・外来語・時代錯誤表現を検出する

**検出パターン：**
- 時代設定がある作品で現代の外来語を使う（例：「ばいばい」「オッケー」「スマホ」）
- 舞台の文化圏に存在しない概念を使う（例：中世ファンタジーで「コード」「バグ」）
- キャラの知識範囲外の語彙を使う（例：山育ちの少女が化学用語を使う）

### B-4. 章間事実整合性チェック

vecmemori の `contradict` を使って、章をまたぐ事実の整合性を検証する。

```python
# 殺害人数の整合性
fact_store(action="contradict", statement="九十九は20人殺した")

# キャラの年齢整合性
fact_store(action="contradict", statement="灯は16歳で鋼は48歳")

# タイムライン整合性
fact_store(action="contradict", statement="灯の両親は灯が社にいた2日目の夜に死亡した")
```

### B-5. 五感ローテーション確認

各シーンで視覚以外の感覚（聴覚・触覚・嗅覚）が2つ以上使われているか確認する。不足している場合は追記する。

---

## Phase C: プロット推敲チェックリスト（本文執筆前に必須）

| # | チェック項目 | 方法 |
|---|------------|------|
| 1 | タイムラインに矛盾がないか | A-1 |
| 2 | 各キャラの知識状態が明確か | A-2 |
| 3 | 伏線の張り→回収が対応しているか | A-3 |
| 4 | 山彦やモブ妖など、後の章で重要な役割を持つ存在が、それ以前に登場・言及されているか | A-3 の拡張 |
| 5 | キャラの台詞が、その時点の知識状態に基づいているか | A-2 の適用 |
| 6 | 時代設定に合わない語彙がないか | B-3 の事前チェック |

## 推敲時の vecmemori 活用

推敲フェーズでは以下の vecmemori 操作を活用する：

```python
# 章間の矛盾検出
fact_store(action="contradict", statement="確認したい命題")

# キャラの全情報を確認
fact_store(action="probe", entity="灯")

# 伏線の状態確認
fact_store(action="search", query="伏線 未回収")

# 世界観の確認
fact_store(action="search", query="世界観 時代 設定")
```

| ツール | 用途 | 使いどころ |

| `web_search` | 時代考証・語彙検証 | 「昭和8年 俗語」「大正 度量衡」等でリアルタイム検証 |

## MoA（Mixture of Agents）推敲

推敲は「論理整合性」「文体品質」「時代正確性」「読者体験」と複数の軸があるため、複数モデルの合議によるチェックが有効です。

### 有効化のタイミング

プロット推敲（Phase A）または本文推敲（Phase B）の直前に、ユーザに MoA の有効化を提案します。

### モデル選択

利用可能なモデルを提案し、ユーザに確認してもらいます：

```
MoA 推敲を有効化しますか？
4つの異なる観点から合議的にチェックを行います。

使用モデル（0〜4個選択可能。多いほど多角的な指摘が得られます）:
1. deepseek-v4-pro — 推論力が高い、日本語対応良好
2. mimo-v2.5-pro — 軽量高速、異なるバイアスで補完
3. glm-5.1 — 中特化、文体への理解が深い
4. qwen3.6-plus — 長文対応、知識の幅が広い

どのモデルを使いますか？（例: 「1,2,3,4すべて」「1,3のみ」）
```

### MoA の実装

`delegate_task` を使い、各モデルに異なる観点の推敲を担当させます：

| サブエージェント | 担当観点 | 指摘の方向性 |
|-----------------|---------|-------------|
| Agent 1 | 論理整合性 | タイムライン・数値・知識状態の矛盾 |
| Agent 2 | 文体品質 | 日本語の自然さ・比喩・五感バランス |
| Agent 3 | 時代正確性 | 語彙・度量衡・文化の時代検証 |
| Agent 4 | 読者体験 | 感情曲線・テンポ・伏線の効果 |
| Agent 5 | ブラッシュアップ | テーマ深化・感情曲線の体感・読後感の質 |

各エージェントの出力を集約し、重複指摘をまとめたうえでユーザに提示します。

## Phase D: ブラッシュアップ（テーマ・感情・読後感）

Phase A〜C が「整合性・文体・時代」のミクロな推敲であるのに対し、ブラッシュアップは「この作品を読んでどう感じたか」という読者視点でのマクロな評価です。

### 問いかけの軸

1. **読後感**: 読んで良かったと思える内容だったか？ 心に残る場面はあったか？
2. **テーマ表現**: proposal.md のテーマ・モチーフが表現できているか？
3. **感情曲線**: 提案された感情曲線通りに感情が動かされたか？
4. **改善提案**: テーマをより深めるために、シーンの構造変更やキャラの行動変更の提案があるか？

### チェック方法

ブラッシュアップは MoA 推敲の Agent 5（ブラッシュアップ担当）として実施する。

```
各エージェントに以下のプロンプトを与える:

「あなたは一読者です。この小説を読み、以下の質問に答えてください:
1. 読んで良かったか？ どの場面が心に残ったか？
2. 提案されたテーマ（『恩と正義の相克』『人と妖の境界』『守るということ』）が表現されていたか？
3. 感情曲線通りに感情が動かされたか？
4. テーマをより深めるために改善できるシーンや行動の変更はあるか？」
```

ユーザから特定シーンの改善案が出た場合は、その案の妥当性も MoA で審議する：

```
「以下の改善案について、テーマ深化・感情曲線・読後感の観点から
 妥当性を審議してください: [ユーザの提案]」
```
