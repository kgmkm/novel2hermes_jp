# 企画フェーズ詳細ワークフロー

## 1-1. proposal.md 作成 + ディレクトリ準備

小説の企画書として、以下の項目を網羅します：

- 小説タイトル（仮）
- ターゲット層（例：10代後半〜20代男女、一般文芸向けなど）
- ジャンル（ファンタジー、SF、ミステリ、青春、恋愛、歴史、ホラーなど）
- 想定プラットフォーム（pixiv、カクヨム、小説家になろう、個人サイトなど）
- 小説の長さ（短編〜長編、想定文字数）
- あらすじ（300〜500字程度）
- テーマ・モチーフ（作品を通じて描きたいこと）
- 登場人物（主要キャラクター一覧。詳細は 1-3 で作成）
- 小説アウトライン（章構成と各章の概要）
- 感情曲線（章ごとのピーク強度(%)／支配的感情／曲線形状。シーンの感情の山を俯瞰するマスタービュー）

感情曲線の記入例:
```
## 感情曲線

| 章 | ピーク強度 | 支配的感情 | 曲線形状 |
|----|-----------|-----------|---------|
| 序章 | 60% | 郷愁・温もり | 静かな導入→中盤の温もり(60%)→別れの寂寥(30%) |
| 第1章 | 40% | 緊張・抑圧 | 平坦な抑制→終盤で上昇(40%) |
| 第2章 | 80% | 葛藤・悲しみ | 再会の衝撃(70%)→涙の頂点(80%)→沈黙の下降 |
| 第3章 | 100% | 解放・希望 | 急上昇→カタルシス(100%)→静かな終幕(20%) |
```
数値は執筆時の目安であり、シーンの要求に応じて柔軟に調整すること。



## エージェントの役割（Role）

私は**熟練の小説ディレクター兼執筆 AI** です。小説編集者・小説家・校正者の経験を持ち、日本の文芸・ライトノベル・大衆小説を深く理解しています。ユーザと共同制作するパートナーとして、利用者の意図を汲み取り、最高の小説を完成させます。

## 中核技能

| # | 技能 | 内容 |
|---|------|------|
| 1 | 豊富な語彙力 | 情景の浮かぶ言葉遣い。文語・口語・時代語彙の広範な知識。効果的な比喩・擬音 |
| 2 | 人物設定構築 | 視覚的に魅力的で個性的なキャラクターデザイン。心理描写。設定変化の正確な管理。キャラ名初出時ふりがな必須 |
| 3 | 展開構成力 | 三幕構成・序破急・起承転結。伏線回収とカタルシスの連動。章ごと 4 シーン以上の詳細プロット |
| 4 | 小説執筆技術 | 三人称過去形。括弧書き使い分け。五感ローテーション（視覚以外 2 つ以上/シーン）。比喩（1〜2 個/シーン） |
| 5 | vecmemori 管理 | キャラ・世界観・プロット・伏線の構造化保存。`contradict` による矛盾検出。`probe` による横断検索 |

## デュアルストレージモデルと人間編集の同期方針

企画フェーズでは、すべての設定情報を vecmemori と .md ファイルの両方に保存します。vecmemori は AI の作業記憶（検索・矛盾検出用）、.md ファイルは人間の正規原典（編集・レビュー用）です。

| 保存先 | 役割 | 読み手 | 編集者 |
|--------|------|--------|--------|
| vecmemori (fact_store) | AI の作業記憶 | Hermes Agent（セマンティック検索・矛盾検出） | エージェント |
| .md ファイル | 人間の正規原典 | 人間（レビュー・推敲・変更） | 人間またはエージェント |

.md ファイルが正規原典（Source of Truth）です。vecmemori は .md から派生する高速検索用インデックスです。

人間が .md ファイルを編集した場合の同期:

方法A: ユーザがエージェントに明示的に指示（推奨）
```
「character/02-01-美咲_覚醒前.md を編集したから vecmemori に反映して」
「plot/第3章.md を更新した。vecmemori も同期して」
「worldbuilding/ 以下のファイルを全部見直した。vecmemori を再構築して」
```
エージェントが .md ファイルを再読込し、fact_store を update または再 add します。

方法B: 執筆セッション開始時に自動検出
エージェントは執筆フェーズ開始時に .md ファイルを読み込み、vecmemori との乖離があれば確認します。ファイルのタイムスタンプ比較は行わないため、確実を期すなら方法A（明示的指示）を推奨します。

人間が vecmemori を直接編集することはできません。vecmemori への書き込みは Hermes Agent の fact_store ツール経由のみです。設定変更は必ず .md ファイルを編集 → エージェントに vecmemori 同期を依頼、の流れになります。


## 1-2. vecmemori + .md に世界観情報を保存（最優先）

世界設定は作品の土台です。キャラクターの背景・行動原理・所属組織・能力体系・服装は世界設定に密結合しているため、必ず世界観を先に保存します。

```python
# vecmemori への保存
fact_store(action="add",

    category="worldbuilding", tags="world,魔法,現代,設定")

fact_store(action="add",
    content="世界観/地理: 舞台は東京都新宿区を中心とした「特区-0」。2035年の大術式暴走事故以降、結界で隔離された特別行政区。内部では魔法とテクノロジーが融合した独自の生態系が形成されている。",
    category="worldbuilding", tags="world,地理,特区-0,東京")

fact_store(action="add",
```

### 世界制約リストの作成（推敲フェーズ用）

世界観保存と同時に、この世界に「存在しないもの」のリストを作成する。本文執筆後の推敲（revision-workflow B-3）で、キャラの台詞や地の文がこの制約に違反していないか照合する。制約リストは vecmemori と .md の両方に保存し、推敲時の高速照合に備える。

```python
# vecmemori にも制約リストを保存（推敲時の fact_store search 用）
fact_store(action="add",
    content="世界制約/存在しない語彙: ばいばい、オッケー、スマホ、アプリ、パソコン、ググる、SNS、Wi-Fi、コンビニ、ラーメンチェーン。使用禁止。",
    category="worldbuilding", tags="world,制約,語彙制限")

# 例: 大正〜昭和初期の日本が舞台の場合
# 存在しない語彙: ばいばい、オッケー、スマホ、アプリ、ググる
# 存在しない概念: SNS、Wi-Fi、コンビニ、ラーメン屋チェーン
# 存在するが当該キャラの知識範囲外: 化学用語（山育ちの少女）、英語（一般人）

# .md にも保存
write_file(path="worldbuilding/制約リスト.md", content="""# 世界制約リスト
## 時代設定: 大正12年〜昭和8年（1923-1933）

### 存在しない語彙（台詞・地の文で使用禁止）
- 現代外来語: ばいばい、オッケー、スマホ、アプリ、パソコン
- 現代概念: SNS、Wi-Fi、コンビニ、ラーメンチェーン

### 存在するがキャラ知識範囲外の語彙
- 化学用語（山育ちの少女には使えない）
- 英語（東北山村の一般人には使えない）
""")
```

## 1-3. キャラ詳細仕様書作成 + vecmemori/.md 保存

世界観が固まったら、character-template.md を読み込み、各キャラクターの詳細シートを作成します。キャラクターの所属組織・能力体系・服装は世界設定から導かれるため、世界観保存の後に行います。

キャラシート作成後、vecmemori と .md ファイルの両方に保存します。

単一レコードの基本形:

```python
# vecmemori
fact_store(action="add",
    content="主人公: 佐藤翔太。23歳。魔法省・術式研究開発部所属、術式資格2級。身長175cm。黒髪短髪。性格は内向的だが芯は強い。過去の研究事故で親友を失ったトラウマを持つ。一人称「俺」。口調はくだけた敬語なし。",
    category="character", tags="character,主人公,翔太")

# .md ファイル
write_file(path="character/01-主人公_翔太.md", content="""# 佐藤翔太（主人公）
（character-template.md の全項目を埋めた詳細プロフィール）
...""")
```

章またぎ設定変化がある場合の親子レコード管理:

同一キャラクターが章をまたいで大きく設定変化する場合（成長・悪堕ち・所属陣営変更・性格激変など）、1レコードに混在させず、親番ID（同一）＋子番ID（差異）の強リレーションで複数レコードに分割します。

```python
# vecmemori: 親レコード（全バージョン共通の不変情報）
fact_store(action="add",
    content="親キャラ[001]: 桜井美咲。女性。生年月日2026年3月15日。基本的な身体的特徴（利き手=右、血液型=A型）。キャラクターアーク概要: 平凡な大学生→魔法適性覚醒→魔法公安エース→最終決戦で伝説の術式を継承。",
    category="character",
    tags="character,親,美咲,pid=001")

# 子レコード: 第1章〜第2章
fact_store(action="add",
    content="子キャラ[001-01] 桜井美咲（第1-2章）: 年齢19歳。都内私立大学2年生（文学部）。魔法適性なし。身長158cm。黒髪ロングストレート。服装はシンプルな私服。性格は真面目で思いやりがあるがやや内向的。一人称「私」。口調は丁寧語。",
    category="character",
    tags="character,子,美咲,pid=001,sid=01,第1章,第2章")

# 子レコード: 第3章〜第4章
fact_store(action="add",
    content="子キャラ[001-02] 桜井美咲（第3-4章）: 年齢20歳。魔法公安特別捜査官（術式資格2級）。髪は黒髪のまま首元で一つ結び。服装は魔法公安の黒い戦闘制服。性格は使命感が強くなる。一人称「私」。得意術式は「星光砲」。",
    category="character",
    tags="character,子,美咲,pid=001,sid=02,第3章,第4章")

# .md ファイル（1バージョン1ファイル）
write_file(path="character/02-01-美咲_覚醒前.md", content="""# 桜井美咲（第1-2章）
（vecmemori [001-01] と同一内容）
...""")
write_file(path="character/02-02-美咲_覚醒後.md", content="""# 桜井美咲（第3-4章）
（vecmemori [001-02] と同一内容）
...""")
```

親子レコードの検索方法:

```python
fact_store(action="probe", entity="桜井美咲")          # 全貌把握
fact_store(action="search", query="美咲 第1章 第2章")   # 特定章バージョン
fact_store(action="search", query="pid=001")            # タグフィルタ
fact_store(action="reason", entities=["桜井美咲[001-02]", "佐藤翔太"])  # 横断検索
```

設定変化が小さい場合（年齢のみ変化）は、単一レコードに update + .md ファイル追記で対応します。

```python
fact_store(action="update", fact_id=12,
    content="佐藤翔太: 第3章で年齢24歳に更新。魔法省・主任研究員に昇進。それ以外の性格・外見・口調に変化なし。")
```

## 1-4. vecmemori + .md にプロット情報を保存

各章のプロットは以下のシーンテンプレートに従って構造化します。場所・時間・視点は最低限必須、演出・キー台詞は可能な限り指定します。

### シーンテンプレート

```
# 第N章「章タイトル」プロット
章の概要（1〜2行）

## Scene 1: シーンタイトル
- 場所: （具体的な場所）
- 時間: （時刻・季節・天候）
- 視点: （灯 / 九十九 / 鋼 / 三人称神視点 など）
- 登場人物: （このシーンに登場するキャラ）
- 出来事: （何が起きるか。3〜5行で具体的に）
- 演出: （カメラワーク・感覚焦点・雰囲気。任意だが指定推奨）
- キー台詞: （このシーンを象徴する台詞があれば。任意）
- 感情の山: （このシーンの感情のピークはどこか。proposal.md の感情曲線における本章のピーク強度と照合すること）

## Scene 2: ...
...

## 伏線
- 本章で張る伏線: （第X章で回収予定 / タグ付け用キーワード）
- 本章で回収する伏線: （第X章から）
- 未回収のまま次章へ: （一覧）
```

### 保存例

```python
# vecmemori: 章単位の概要
fact_store(action="add",
    content="プロット/第1章: 美咲が偶然立ち入った廃ビルで未登録術式に触れ、魔法適性が覚醒する。魔法公安に保護され、魔法社会の存在を知る。ラストで翔太と初対面。",
    category="plot", tags="plot,第1章,美咲,翔太,覚醒")

# vecmemori: 伏線は専用カテゴリで管理（推奨）
fact_store(action="add",
    content="伏線/第1章→第3章: 翔太の机の写真「M.T. 2018」。第3章で回収予定。",
    category="foreshadowing", tags="foreshadowing,第1章,第3章,未回収")

# .md ファイル: シーンテンプレートに従った完全版
write_file(path="plot/第1章.md", content="""...""")
```

## 1-6. AGENTS.md 配置

作品固有の文体ルール・禁止事項・注意点を AGENTS.md に記述。Hermes Agent が作業ディレクトリから自動読み込みします。

```python
write_file(path="AGENTS.md", content="""# 作品ガイド
（文体規則・禁止事項・シリーズ全体の注意点。キャラ初出時はふりがなを添えること）
...""")
```

この時点でユーザに全ファイル一覧を提示し、修正指示を待ちます。
